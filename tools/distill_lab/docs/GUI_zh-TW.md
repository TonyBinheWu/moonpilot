# 瀏覽器操作手冊

介面在 DGX Spark 本機執行，使用既有 `lab.py` 與 `car.py`。資料、模型、工作資料庫與紀錄都保存在 Spark；頁面沒有展示用假數據。

## 啟動與更新

第一次使用依 README 複製專案、安裝 `uv`、`ffmpeg`、`rsync`，再執行 `bash bootstrap.sh`。已安裝上一版的人，從專案根目錄更新：

```bash
git pull --ff-only
cd tools/distill_lab
uv pip install --python upstream/.venv/bin/python -r requirements-ui.txt
bash gui.sh
```

如果已在 `tools/distill_lab`，不必重複 `cd`。Spark 本機瀏覽器開啟 [http://127.0.0.1:8501](http://127.0.0.1:8501)。要從 Windows 操作，在 PowerShell 建立通道：

```powershell
ssh -N -L 8501:127.0.0.1:8501 spark
```

`spark` 是你設定的 SSH 別名，也可換成自己的 `帳號@Spark位址`。保持通道開啟，Windows 瀏覽器同樣開 `http://127.0.0.1:8501`。關閉通道只中斷網頁連線，已啟動的背景工作繼續執行。

介面只監聽 localhost，保留 CORS／XSRF 防護。它沒有多使用者登入與權限分級，不要直接公開服務埠。SSH 使用 Spark 上已設定的金鑰與主機指紋；GUI 不接收密碼、不接受任意 shell 指令。第一次連線裝置時，需先在 Spark 終端機確認 `ssh comma` 能以預期金鑰與指紋登入；GUI 不自動信任未知主機。

自訂工作位置：

```bash
DISTILL_LAB_WORK=/home/tony/driving-data bash gui.sh
```

使用舊資料時，指向原本 `work/` 即可。不同位置是不同實驗室。介面的資料夾路徑指 Spark 的檔案系統，不是 Windows 磁碟機。不要在背景工作尚未完成時移動或刪除工作目錄。

## 頁面與操作順序

| 頁面 | 操作 |
|---|---|
| 總覽 | 環境檢查、下載固定版本教師模型、確認可用磁碟 |
| 資料 → 取得資料 | 讀取裝置、選行程下載；或指定 Spark 本地資料夾／公開片段 |
| 資料 → 定位與切分 | 選定位來源、檢查整趟行程、建立訓練／驗證組 |
| 資料 → 預覽與品質 | 選片段與影格，查看雙鏡頭、車速與品質報告 |
| 訓練 | 設定名稱、步數、batch、學習率與驗證間隔；開始／停止／續訓 |
| 評估與匯出 | 選 checkpoint、評估、比較實驗、匯出新候選 |
| 模擬與微調 | 下載／啟動世界模型、選訓練片段微調、開啟互動模擬 |
| 車端部署 | 暫存、Chestnut 編譯、benchmark、啟用與回復 |
| 工作紀錄 | 查看工作、錯誤、操作參數，停止可中斷的工作 |

「讀取裝置與行程」是背景工作，完成後按左側「重新整理頁面」取得行程選單。讀取內容限必要裝置識別、版本、行程及本工具的候選／備份紀錄。

## 資料與訓練

大型影片不經 Windows 瀏覽器上傳：以 SSH／rsync 從裝置取得，或選 Spark 上已有的資料夾。需要原始雙鏡頭與完整 rlog；只有影片不能直接進入訓練。

`raw-gnss` 需要上游要求的 UBlox 與有效姿態資料。`logged-ecef` 必須真的有有效 ECEF 狀態，屬不同品質的研究標籤。程式不自動降級切換。整趟行程有任何片段失敗，工作就會顯示失敗，保留成功片段及逐片段報告。已匯入的片段用「重新定位」，不要再次複製同名資料。

正式實驗至少兩趟行程。單片段短測試沒有驗證組，不能完成正式候選匯出。公開匿名片段也不能保證來自不同原始行程，報告會記錄限制。

訓練曲線每 3 秒讀取真實 JSONL，較長實驗顯示最近約 4 MB 紀錄；完整檔案保留。沒有 GPU 時仍可開介面、查看資料與紀錄，GPU 訓練會明確失敗。

## 背景工作

狀態保存在 `jobs/jobs.sqlite3`，每個工作有獨立 `.log`。頁面開啟本身不啟動下載、訓練或車端操作。關閉瀏覽器、重整頁面或重新啟動 GUI 都不會主動終止背景工作。Spark 關機、系統終止程序或登出政策仍可能終止工作，不能把這個功能當成電源中斷續跑。

工作遇到資源衝突時會拒絕啟動，不會默默排隊並在數小時後替你啟用模型。同一 GUI 目錄會阻擋重複的資料／訓練工作，以及同時進行的車端操作。請勿另從 Notebook／CLI 同時修改同一份資料，手動命令不會自動被 GUI 工作資料庫納管。

停止一般工作先送 SIGINT；30 秒後仍未結束才送 SIGTERM，45 秒仍未結束才終止該工作程序群組。續訓從最後完整保存的 checkpoint 開始，不保證停止前的最後一步已寫入。重新切分資料或改 batch／學習率後，原實驗可能無法續訓。

背景存活狀態使用作業系統檔案鎖確認，避免 PID 重用或容器 PID 差異造成誤判。若管理程序中斷、子程序仍持有執行鎖，顯示「需檢查背景程序」，並保留資源鎖。介面不猜測 PID 去終止其他程序；請在 Spark 終端機核對紀錄中的程序，不能刪除鎖檔來強迫啟動第二次訓練。

## 模擬

世界模型服務會持續占用 GPU，啟動後請看工作紀錄確認載入結果。一般訓練、評估與匯出前，先停止世界模型服務。

微調從訓練組選片段，互動模擬從驗證組選片段。互動模擬使用原專案 Raylib 視窗，出現在 Spark 圖形桌面；本版沒有瀏覽器模擬畫面串流。沒有圖形桌面時，互動按鈕停用，背景微調入口仍可使用。世界模型與 NVFP4 路徑尚需 Spark 實測。

## 車端部署

GUI 呼叫同一份 `car.py`，完整限制見 [部署手冊](DEPLOYMENT_zh-TW.md)，保留 checksum、軟體介面、offroad、模型選單與 benchmark 檢查。

1. 讀取實際裝置身分、版本與停車狀態，確認是預期裝置。
2. 選 Spark 已匯出的候選，執行「傳送並在車端暫存」。工具依自身內容 hash 分開保存，候選有固定位置。
3. 選實際攝影機解析度，在 Chestnut 編譯，再做數值與延遲測試。
4. 重新讀取裝置，核對候選的 benchmark。畫面是上次讀取結果；每次操作會重新檢查身分與停車狀態。
5. 先在車端模型選單選回預設模型。確認封閉場地與評估條件，輸入確切 `裝置／候選`，再按「備份並啟用候選」。
6. 記錄備份位置，手動重啟後核對現用檔案、Chestnut 狀態與真正的 modeld 載入紀錄。
7. 回復時從實際車端清單選備份，輸入確切 `裝置／備份`，在 offroad 狀態執行。

車端工作開始後不提供停止按鈕。若 SSH 意外中斷，工作失敗不等於遠端操作已停止，結果可能未知。先重新讀取裝置、檢查車端紀錄和鎖狀態，再決定下一步。GUI 不自動重試啟用／回復，也不自動重開機。

## 驗證範圍

以 Streamlit AppTest 驗證頁面、表單與按鈕操作；以真實本地子程序驗證背景工作、停止、錯誤結果與執行鎖。AppTest 是介面邏輯測試，不是實體瀏覽器截圖或 Spark／車端整合測試。遠端命令使用測試替身確認裝置身分及 offroad 防護，沒有連線真實車輛。

尚未在 Tony 的 Spark、原始 3X 行程或 Chestnut 上跑完流程。GUI 不是已訓練模型，也不代表已通過駕駛品質驗證。
